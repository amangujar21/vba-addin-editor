# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Windows-only, offline Tkinter/ttk app that edits VBA source (and existing OOXML parts) inside Excel `.xlam`, PowerPoint `.ppam` and `.pptm` files **in place**: verified candidate → atomic commit, keeping the old file as a same-folder backup unless the user turned automatic backup off. No Office automation, with one exception: live reload (`platform/office_live.py`), which on Save closes an add-in Office has loaded and loads it again. VBA parsing/writing goes through `pyopenvba==6.6.0` (exact pin; the adapter imports its internals).

## Commands

```powershell
pip install -e .[dev]                      # re-run after adding new modules under src/
python -m pytest tests -q                  # full suite (5 "live" tests skip without real fixtures)
python -m pytest tests/unit/test_ribbon_service.py -q
python -m pytest tests -k "class_delete" -q
python -m pytest tests -m live -v          # live Office gate; needs tests/fixtures/* (gitignored)
python scripts/make_office_fixtures.py     # Excel/PowerPoint author those fixtures (Office installed)
$env:VBAAE_LIVE_OFFICE=1; python -m pytest tests -m live   # also load each saved file in real Office
python -m ruff check .
python -m pyright src                      # baseline has ~26 pre-existing errors; don't add new ones
python -m vba_addin_editor                 # run the GUI
python -m vba_addin_editor --self-test path\to\file.xlam
python -m vba_addin_editor --self-roundtrip path\to\file.ppam
scripts/build.ps1 -Onefile                 # dist\VBAAddinEditor.exe (dev build)
scripts/build.ps1 -Release                 # strict gate: clean tree, tests, lint, pyright, real fixtures
```

- The installed `vba_addin_editor` may be an editable install of another checkout: run tests here with `PYTHONPATH=src` (or reinstall).
- Build smoke tests need `tests/fixtures/xlam/Demo.xlam`; `-Release` also needs `RealAddin.xlam`, `RealAddin.ppam`, `RealPresentation.pptm`. `tests/fixtures/` is gitignored. A synthetic Demo can be made with `conftest.build_xlam`. Never copy the user's own add-ins into the repo.
- Releases so far: onefile exe + `.sha256` zipped as `VBAAddinEditor-vX.Y.Z-Windows.zip` on GitHub. Version lives in three places: `pyproject.toml`, `src/vba_addin_editor/version.py`, `packaging/VBAAddinEditor.spec`.
- Some shells can't launch `dist\...exe` directly; use PowerShell `& ".\dist\VBAAddinEditor.exe"` or `cmd /c`.

## Architecture

Layers under `src/vba_addin_editor/`:

- **domain/** — `DocumentSnapshot` (immutable open-time state, the *trusted* source) vs `DocumentDraft` (editable `ModuleDraft`s + `XmlPartDraft`s; `XmlPartDraft.is_new` and `BinaryPartDraft`s are members the next save *adds* — today only a first `customUI/customUI14.xml`, ribbon icons and their `.rels`). A UserForm's layout is a `FormStorage` (every stream under its designer storage plus each storage's CLSID): `FormDesignSnapshot.storage` holds it as opened, and `ModuleDraft.form_storage` is set only for a form the draft adds or whose layout it edits (`new_forms()`, `changed_form_layouts()`; `form_storage_of()` gives either). `capabilities.py` classifies each component from the VBA `PROJECT` stream + dir records (standard / class / document / designer / userform); only snapshot capabilities authorize delete/rename — draft flags never do.
- **adapters/** — the only places bytes are touched. Both adapters take a package as a path *or* as bytes (`PackageSource`); open and save pass bytes. `pyopenvba_adapter.py` is the single VBA seam (in-memory hosts via `_open_host`, a decoded-source cache keyed by compressed stream, build/verify candidate, delete/rename replay, PROJECT scrub shim written for pyOpenVBA 3.4.0; UserForm storages: `_read_storage`/`_write_storage` copy one byte for byte, `read_form_design` parses one for display, `edit_form_storage` applies a `FormLayoutEditor` edit (pyOpenVBA's form writer, plus site position/name/tip and form size it lacks) to a scratch copy and returns the new storage, `new_form_storage` uses `create_form`; signature-part removal edits via `pyopenvba._package_signature`). `ooxml_package_adapter.py` is the only code that reads/rewrites ZIP entries; the GUI never touches package members. `xml_codec.py` preserves each part's codec/BOM/newline; editor text is LF-normalized.
- **services/** — `save_service.py` runs the composite transaction in memory: VBA replay and changed XML parts go into one candidate built from `baseline.package_bytes`; `verify_candidate(..., allowed_non_vba_changes=...)` permits differences only on the exact changed XML paths; the candidate is written once and committed; post-commit verification proves by file identity (volume, file id, size, mtime) that the path holds the verified candidate and the backup holds the old file, reading a file only when identity cannot prove it. `session_service`/`recovery_service`/`history_service` implement draft sessions, recovery checkpoints and undo (`HistoryCommand` ops: `text`, `xml_text`, `rename`, `add`, `delete`, `replace_all` with `{"modules","xml"}` snapshots for multi-target undo). `ribbon_service.py` is pure-text customUI ↔ VBA callback linking (lexical XML scan so it works on mid-edit XML), plus structural edits on its `element_tree` (move a control, group into a menu, image relationships). `port_service.py` ports a ribbon control from another add-in: `portable_controls` / `port_targets` / `plan_port` (pure, on a `clone_draft` of the target; a lexical VBA tokenizer + top-level item parser walk the callback's dependency closure, decide renames with `_Namer`, rewrite tokens/strings/XML, copy images, hook IRibbonUI variables into the target onLoad) and `apply_port` (copies the clone's new/changed modules, parts and images into the real draft inside `_batch_edit`). `portable_forms` / `plan_form_port` copy whole UserForms the same way (`_add_form`: code rewritten for renames, `fresh_designer_header` gives new `VB_Base` ids, layout copied as its `FormStorage`); a ribbon port copies the forms its macros use. `form_service.py` is the designer's draft API (`add_blank_form`, `edited_layout`/`set_layout`, `rename_in_code`, `ensure_handler`, `design_of` with a small cache). New class modules keep a copied stream-form header (`VB_Base` present) through `pyopenvba_adapter._new_module_source`. `starter_service.py` starts from nothing: `create_blank_file` writes pyOpenVBA's Office-authored blank template (via `pyopenvba_adapter.blank_template_bytes`; `.ppam` = the `.pptm` template with the add-in main content type) with `write_verified` and returns `(bytes, written_fingerprint)` so `SessionService.open(path, written=...)` / `MainWindow.load_path(..., written=...)` never read it back; `add_starter_ribbon` adds a new customUI14.xml part plus its `_rels/.rels` link (and a content type only when `.xml` isn't `application/xml`), refused by `ribbon_blocker`. `icon_service.py` makes 32×32 PNGs with Pillow (imported lazily; the spec excludes its font/CMS/WebP/Tk modules) and wires an icon into the draft (ribbon part, `customUI/_rels/*.rels`, `[Content_Types].xml`, image).
- **platform/** — `commit_replace` (rename when it preserves the file's security/attributes/streams, else `ReplaceFileW`), exclusive-access probes, Office process detection, `settings.py` (user preferences). `office_live.py` is the only code that talks to Office (pywin32 COM, late bound, imported lazily): `locate(path)` says whether a running Office has the file loaded (Excel via the Running Object Table, so the right instance among several; PowerPoint via `AddIns`/`Presentations`) and whether it holds unsaved changes; `HostSwap` (a context manager; COM objects belong to one thread, so make, use and drop it on the save worker) `unload()`s it before the commit and `reload()`s it after. `SaveService.save_addin(draft, swap=...)` builds and verifies the candidate while the add-in stays loaded, then unloads, commits (Office-running gate skipped; lock and fingerprint gates kept) and reloads in a `finally`, so a failed commit reloads the old file; outcome in `result.details` (`live_host`, `live_reloaded`, `live_reload_error`). `MainWindow.save` asks Office first (`_ask_office`, only when the host process runs and `Settings.live_reload` is on); when Office answers that it does not have the file loaded, `host_block(..., host_checked=True)` checks only the file lock.
- **ui/** — `main_window.py` owns everything; the Code and Package XML views each use a `CodeEditor` (`xml_editor.py` subclasses it). `text_context_menu.py` provides right-click menus with `add_extra()` hooks. Find/replace is one inline bar per `CodeEditor` (`show_find`); the text widget's Ctrl+F/Ctrl+H bindings return `"break"` so the window-level bindings (for focus outside an editor) never fire a second time. `ribbon_dialogs.py` holds the Add Button / Add Menu / Import Button forms; `MainWindow.apply_ribbon_button` / `apply_ribbon_menu` / `apply_port_plan` do the edit and are what tests call.
  - `theme.py` holds the only colours (`DARK` / `LIGHT` palettes); `apply_theme` (called in `MainWindow.__init__` before any widget exists) sets ttk `clam` styles, the Tk option database for classic widgets, and named fonts (`VbaaeCode` is shared by every editor, so zoom is one font change). Use a named style or `theme.palette()`, never a hex colour in a widget call. Dark title bars come from `DwmSetWindowAttribute`; `run_gui` keeps the root withdrawn until built because Windows 10 only paints it before first show.
  - There is no Win32 menu bar (Tk cannot colour it): the header holds `ttk.Menubutton`s (`_header_menu`), Alt+letter/F10 post them, and `_set_menubar_state` disables them while a worker runs.
  - `form_designer.py` (`FormDesigner`) is the UserForms view: tree (iids `form::<Form>/<control>/…`), a canvas drawing at 4/3 px per point (`control_box`, `press`/`motion`/`release`/`double_click` take event-like objects, which tests pass), an inspector of `_Row`s (`rows[key].var` + `commit()`). Edits go through `MainWindow.apply_form_edit(module, edit, what, select=, rename=)` (one `_batch_edit` step); `new_userform`, `import_userform(path)`, `open_form_code(module, control, create=)` are the window's commands. `forms_tree`/`form_props`/`form_code_btn` are aliases of its widgets.
  - Layout follows the "night" redesign mockup: header (logo, menus, file + host pill, Ctrl+K command box, "N changes", Save), an activity rail (`RailButton`s in `widgets.py`) that selects pages of a tab-less `Hidden.TNotebook`, per-view sidebar (`widgets.Sidebar`, made through `_build_sidebar`, which keeps them in `_sidebars` for `apply_palette` on a theme switch: caption, filter, tree with a `badge` column M/A/R/🔒; there is no legend), a breadcrumb bar per editor, and a full-width status bar. Rail order = page order = Ctrl+1..4: `0 Code`, `1 Ribbon`, `2 UserForms`, `3 Package XML`; `_on_view_changed` refreshes the view switched to. Icons are Segoe Fluent/MDL2 glyphs via `widgets.icon()` (text fallbacks without the font); no image files.
  - Code view sidebar = MODULES + PROCEDURES. The outline (`_refresh_outline` on a timer, `_follow_outline` follows the cursor) marks macros a ribbon control runs with the ribbon glyph, else `fn`/`get`/`let`/`set` (`OUTLINE_MARKS`); `+` = `add_procedure` (name from `_prompt_name`). Its after/after_idle handles are cancelled in `_cancel_afters`.
  - Ribbon view = `ribbon_designer.py` (`RibbonDesigner`: tree with filter + health line/problems-only, `ribbon_preview.RibbonPreview` canvas, `_Inspector` form of `_Field`/`_MacroField`, `_MacroPeek`; pure helpers `procedure_source`, `drop_zone`). It never keeps its own XML: every operation flushes editors, reads `part.text`, applies a pure `ribbon_service` "designer edit" through `_batch_edit` (one undo step), and `_batch_edit` → `_refresh_ribbon_views()` refreshes it. Tree iids are `e<element index>` and change with structural edits; selection is restored by control id (else index), and `_apply` re-selects an attribute-edited control that was the selection (its id may have changed). A form field commits against the element it was *loaded* for (`_Inspector.element`/`.text`, re-found by `_resolve`), because a click on another row moves the selection before the entry's `<FocusOut>`; Combobox focus-out into its own `popdown` does not commit. A control added in the designer keeps a placeholder id (`_fresh`) until its label is first typed. Ribbon command results go to the ribbon view used last (`_ribbon_surface` "design"/"xml", `_reveal_ribbon`); menu commands that used the XML cursor act on the designer selection when it is showing. Ribbon parts in the XML view get a "Design view" crumb button (`show_ribbon_design`); `ribbon_panel.py` is gone.
  - `menu_dropdown.py`: clicking a menu/splitButton in the preview (`RibbonDesigner._pick`) opens `MenuDropdown`, canvas `DropPanel`s `place`d over the designer (anchored by `RibbonPreview.cell_box`, cascades for submenus) plus a `MacroPicker`. Its state is only `chain` (control keys); `sync()` redraws it from `designer.elements` at the end of every `_show_selection`, so edits/undo keep it current. Edits go through designer methods (`insert_at`, `change_macro`, `rename_control`, `move_control`, `delete_control`; `_macro_plan` makes plain-Sub wrappers or new callback Subs) which use `_apply`. Tests call `press`/`hover_at`/`add`/`context_action`/`picker.pick()` and `panel.finish_rename(True)`; key events don't reach the withdrawn test window. The preview's "+" after a custom group name → `add_to_group`.
  - `command_palette.py` (Ctrl+K) lists every enabled header-menu entry (invoked by index), modules, XML parts and procedures; `>` = commands, `@` = procedures. `CodeEditor.baseline_provider` drives the gutter change bars.
  - The save review is `review_dialog.ask_review` (imported into `main_window`); a successful save without notes shows a `Toast`, not a message box. "N changes" runs `save()`, i.e. opens that review.
  - `highlight.py` colours only the visible lines ± `MARGIN_LINES` on idle (whole-module colouring is ~250 ms on 10k lines). `CodeEditor._schedule_view_update` batches gutter + colouring; scrolling of any kind reaches it through `yscrollcommand`.
  - Pack bars (status bar, banner, wait bar, dialog button rows) *before* the expanding widget in packing order, or a small window pushes them off-screen.

## Invariants that are easy to break

- Never read back a file the editor wrote (candidate, committed add-in, backup, captured session copy). Defender scans a freshly written macro package on its first open **for read**, seconds for a large project; stat, rename and write-only opens do not trigger it. Verify writes through the writing handle (`write_verified`, `write_bytes_atomic`), and treat `FileFingerprint.written_identity` as proof of content while the path still has that identity. The one deliberate exception is `platform/prescan.py`: after a successful save `MainWindow._start_prescan` opens the saved file on a daemon thread so the scan is spent before Office loads it (status bar: "Antivirus scanning …" → "… ready for Office"). Its handle fails the exclusive-access probe while the scan runs, so `_run_in_background` and `restore_backup` call `Prescan.settle()` first; the pending open cannot be cancelled. It holds the GC pause (`_hold_gc`, nestable) until the thread has ended.
- The fast rename commit is only allowed when `rename_commit_preserves_metadata` holds; otherwise `ReplaceFileW` must do it. Lock probes ask for write+delete access, never read.
- Automatic backup is a user setting (`Settings.auto_backup` → `SaveService.auto_backup`, default on). UI text that promises a backup must check it.
- Open and save both run through `MainWindow._run_in_background` with `_saving` set; it disables cyclic GC while the worker runs so Tk variables are never collected off the Tk thread. Don't touch Tk from the worker.
- No change → no write. Office host running / file locked / fingerprint changed → save blocked, draft kept.
- Untouched package members (including malformed baseline XML) must stay byte-identical; only XML in the change set is parsed/validated. Don't reintroduce parse-all verification.
- The ZIP entry set may change only by `draft.added_member_paths()`, `draft.removed_member_paths()` and an approved signature drop. `build_package(..., additions)` refuses names that exist or are unsafe; both verifiers allow exactly those names and the XML verifier checks their bytes. Removals (`DocumentDraft.removed_parts`) are only images (`is_removable_member`) that no ribbon control shows: `icon_service` adds them when an icon is replaced or by `remove_unused_images`, and nothing else may. Undo of package additions/removals goes through the `"package"` snapshot in `_batch_edit`; recovery stores images as base64 `added_parts` and removals as `removed_parts`.
- All files open and stay editable: password-protection detection was removed after false positives; the adapter always passes pyOpenVBA's `allow_protected` (a separate authentication layer will gate this later). XML-only saves must still keep `vbaProject.bin` byte-identical. OPC signatures block XML edits.
- Live reload: never call `GetObject(path)` (it opens a file that is not open); find workbooks through the ROT. A `.ppam` stays locked after `Loaded = False` until `AddIns.Remove`; reload re-adds it and restores `Registered`/`AutoLoad`. Office rebuilds a reloaded add-in's ribbon only when its window is next activated, so while the editor has the foreground the new tab is not there yet (the live test brings Office to the front, as a user does). Excel's `Workbook.Close`/`Workbooks.Open` from COM skip `Auto_Close`/`Auto_Open`, so `HostSwap` runs them (`RunAutoMacros`). Tests never reach real Office: an autouse fixture in `conftest.py` replaces `office_live.locate`; live-reload tests opt back in.
- Ribbon images must be linked with `…/officeDocument/2006/relationships/image` (`rs.IMAGE_REL_TYPE`). 0.6.0 wrote `…/office/2006/relationships/images`, which Office silently ignores (blank button, no error); `rs.LEGACY_IMAGE_REL_TYPE` is detected on open and repaired. Package-structure tests can't catch this kind of bug; check icon changes in real Excel.
- Document modules (`ThisWorkbook`, sheets) are never deletable/renamable. Verified UserForms (`project_item_kind == "userform"`) are delete-only; other designers stay locked.
- A save writes a UserForm layout only by copying a finished `FormStorage` (new forms before `add_module`, so pyOpenVBA declares them `BaseClass`; edited ones replace their storage and set `host._pending_mutation` so the compiled cache is invalidated). Never call `host.forms()` on a host that will `save()` — pyOpenVBA writes back any form it has read; layouts are edited on a scratch CFB in `edit_form_storage`. Verification requires every form storage to equal the draft's (`_expected_layouts`) or, untouched, the original byte for byte; new forms must be declared `BaseClass` with the MSForms reference present.
- An edited layout must drop `TypeInfoVer` from its `\x03VBFrame` header (`edit_form_storage` does): Excel refuses an edited form that keeps it ("The ActiveX Designer's Type Information does not match what was saved"), even with the number raised. This only shows when Office loads the file without recompiling: a checker that adds a module through the VBA object model first hides it, which is why `scripts/office_check.py` runs a report module saved in the file.
- In `MainWindow`, editor widgets hold unflushed text. Call `_flush_all_editors()` before reading/mutating the draft. `_checkpoint_now()` flushes editors, so after mutating the draft programmatically reload editors **before** checkpointing (see `_batch_edit`). `on_module_selected`/`on_xml_part_selected` ignore re-selection of the already-shown item; navigate with `_open_module_at` / `_open_xml_at`.

## Tests

- `tests/conftest.py` builds synthetic packages (`build_xlam`, `build_xlam_with_class`, `build_pptm`, `build_xlam_with_ribbon`); these are not a substitute for the live-Office gate.
- GUI tests create a real withdrawn `tk.Tk()`, set `VBAAE_SESSION_ROOT` to a temp dir (settings live there too, and the on-disk source cache stays off), and monkeypatch `messagebox` / `ribbon_dialogs.choose` / `main_window.ask_review` instead of opening modal dialogs (an autouse fixture in `conftest.py` makes an unpatched review dialog fail instead of hang). Never call `tk_popup()` in tests (use `TextContextMenu.prepare_menu()` / `RibbonDesigner.prepare_context_menu()`); for the outline's `+`, monkeypatch `MainWindow._prompt_name`.
- Ribbon view tests (`tests/integration/test_ribbon_designer_ui.py`) drive the designer like a user: `window._show_view(1)`, `select_start(element.start)`, set a field's `var` and call its `commit()`, then assert on `draft.xml_part_by_path(...).text` and undo. Results of ribbon commands are asserted in the designer (`ribbon_designer.selected_element()`, `.part_path`) unless the test opened the XML view first.
- GUI tests share one settings file (`%TEMP%\vbaae-test-sessions\settings.json`, or `VBAAE_SESSION_ROOT`): a test that turns a setting off must turn it back on.
- `tests/integration/test_live_reload_office.py` (needs `VBAAE_LIVE_OFFICE=1`) drives real Excel and PowerPoint: adds macros and buttons in two rounds and saves while the add-in is loaded, then runs the macros and clicks the new buttons on Office's ribbon through UI Automation (`scripts/ribbon_click.ps1`). It skips PowerPoint while PowerPoint is open.
- `pyopenvba` upgrades: re-read its `_host.py` save path and `vba.py` mutation methods first; `pyopenvba_adapter.py` is the only upgrade seam.

## Project state

`README.md` holds user-facing behavior, the safety model and the release gate. Code comments cite "plan N.N" sections from implementation plans that were removed from the tree; they are in git history before the commit that added this file. Live gate: `scripts/make_office_fixtures.py` + `VBAAE_LIVE_OFFICE=1 pytest -m live` ran green for 0.12.0 (Excel and PowerPoint load and run copied, edited and new UserForms; `ExistingMalformedPart.ppam` is a customer file and was not available). For 0.13.0 only `tests/integration/test_live_reload_office.py` was run live (Excel and PowerPoint, both green). `-Release` still fails on the pre-existing pyright errors (25), so releases remain `-Onefile` dev builds from the GitHub workflow. Known bug: a module body that starts with a blank line fails candidate verification ("Body mismatch"), because `split_attribute_header` drops the blank line on re-read; the save is refused and the original is untouched.
